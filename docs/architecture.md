# 架构与模型边界

## 1. 设计目标

AgentComSim 面向“智能体任务能否在网络与计算共同约束下按期、保质完成”这一问题。最小分析单位不是孤立数据包，而是包含多个因果阶段的任务。平台将任务图、消息传输、计算排队、调度策略和语义质量放在同一实验流程中。

```text
任务轨迹生成 → 策略独立调度 → 网络/计算离散事件 → 任务指标 → 跨种子统计
                                      ├─ PyTorch 采样、训练与推理
                                      └─ ns-3 CSV 导出与单向结果校准
```

## 2. 参考任务图

```text
感知上传 ─→ 感知计算 ─┐
                      ├─→ 规划传输 ─→ 规划计算 ─→ 控制下发
工具传输 ─→ 工具计算 ─┘
```

感知与工具分支并行，二者完成后才能进入规划。`task_id` 标识任务，`cause_id` 标识事件，`parent_cause_id` 表示上游原因。`task-<id>` 和 `task-<id>-join` 是任务根节点与汇合节点的逻辑标识，不是网络或计算资源上的耗时事件。

## 3. 模块职责

| 模块 | 职责 |
|---|---|
| `models.py` | 任务、模态、调度上下文、因果事件和运行结果 |
| `config.py` | 类型化配置、YAML 安全读取和解析后配置保存 |
| `trace.py` | 在仿真前采样完整任务轨迹，落实共同随机数 |
| `engine.py` | SimPy 网络与计算资源、任务 DAG 和事件记录 |
| `policies/` | FIFO、静态优先级、TUS 与神经策略适配器 |
| `experiment.py` | 到达率—种子—策略实验矩阵和跨运行统计 |
| `reporting.py` | CSV、JSON、YAML、JSONL 和性能图 |
| `neural/` | 特征、数据集、MLP、训练与安全 checkpoint 加载 |
| `ns3/` | 数据包级场景、外部 ns-3 进程和结果校验 |
| `web/` | 调用同一核心 API 的本地 Streamlit 工作台 |
| `cli.py` | 所有用户工作流的统一命令行入口 |

## 4. 调度接口

策略实现 `priority(context)`，数值越小越先服务。上下文包含当前事件、任务截止期限、消息大小、网络与计算队列状态。策略还可实现 `should_compress(context)` 和 `compression_parameters(modality)`。

网络资源容量为 1，计算资源容量由 `compute.workers` 决定。SimPy `PriorityResource` 采用非抢占式优先级：正在服务的消息或计算不会被新到的高优先级事件中断。同优先级请求保持 FIFO 顺序。

TUS 分数由剩余关键路径、期限紧迫度、语义效用密度和事件类别奖励组成，调度优先级为分数的相反数。只有视频和图像感知消息可进行有损压缩；工具、规划和控制信息不做此类压缩。

## 5. 指标定义

任务成功必须同时满足：

1. 任务完成时间不晚于绝对截止时间；
2. 任务语义质量不低于 `workload.minimum_quality`。

任务时延为完成时间减去到达时间。单次运行先计算任务 P95 时延，实验汇总再对独立运行的 P95 值求均值和置信区间，而不是把所有运行的任务混合后重新求 P95。

预热期只影响任务级指标的任务筛选。当前 `total_bytes` 和压缩比例统计整个仿真过程，包括预热期；比较策略时应保持同一时长和轨迹。

## 6. 公平性与可复现性

每个“到达率—种子”只生成一次完整轨迹。所有策略复用相同的到达时间、模态、消息大小、计算需求与截止期限；引擎深拷贝任务，防止压缩状态或完成时间污染其他策略。配置、逐次结果和汇总统计随实验一起保存。

## 7. 当前边界

- 默认网络是单瓶颈链路和固定基础时延，不是任意拓扑或无线信道模型。
- 语义质量由任务系数抽象，不执行真实视频编码、模型推理或语义评价模型。
- A2A 与 MCP 在任务语义中体现为智能体协作和工具调用，不实现其线上协议栈。
- ns-3 是单向数据包级桥接，不与 Python 内核进行闭环时间同步。
- 神经调度器是 TUS 模仿学习基线，不声称必然超越教师策略。
